# Himalaya CLI для Nod

Небольшая нативная ARM64-обёртка над Himalaya 2.2.1 для чтения почты по IMAPS. В репозитории нет данных реальных ящиков и секретов.

## Команды

- `check` — проверяет соединение, прочитав не более одного заголовка из INBOX.
- `mailboxes` — список папок.
- `envelopes [папка] [страница] [размер]` — заголовки писем, максимум 100 за вызов.
- `message <числовой-ID> [папка]` — читает письмо, не запрашивая отметку «прочитано».

Остальные команды, включая отправку, удаление, перемещение и изменение флагов, не предоставлены. SMTP не конфигурируется.

## Защита данных

Nod передаёт IMAPS-адрес сервера, логин, пароль и адрес ящика в защищённых полях окружения. Обёртка записывает Himalaya TOML во временный каталог с правами `0700` и файл с правами `0600`, запускает Himalaya без передачи пароля в аргументах и удаляет временную конфигурацию после команды. В аварийном завершении процесса ОС может не выполнить очистку временного файла.

Первое подключение рассчитано на один IMAP-ящик. Возможность нескольких аккаунтов в Nod требует отдельной проверки.

## Сборка

Нужны Zig для `aarch64-linux-musl` и официальный архив Himalaya 2.2.1 для `aarch64-linux`. Компиляция обёртки:

```sh
zig cc -target aarch64-linux-musl -O2 -static -Wall -Wextra -Werror connector.c -o himalaya-nod-connector
```

Для пакета положите `himalaya-nod-connector` и официальный исполняемый файл `himalaya` из релиза Himalaya 2.2.1 в корень `tar.gz`. Пакет должен соответствовать ARM64-среде Nod.

## Статус проверки

Исходник скомпилирован как статический ARM64 ELF с `-Wall -Wextra -Werror`. Himalaya принял создаваемый TOML; проверен только заведомо несуществующий тестовый домен `.invalid`, реальный почтовый ящик не подключался. Тесты не подтверждают доступность сети или подлинность учётных данных.
